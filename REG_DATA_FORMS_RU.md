Базовый URL API из `lib/config.dart`: **http://gruzoperevozki72.ru**

**Свод сценариев и бизнес-логики (все промпты):** [docs/app_scenarios_ru.md](./docs/app_scenarios_ru.md)

Документ составлен по экранам Flutter (`lib/pages/…`). Если на сервере изменят поля API, актуальность нужно сверять с PHP.

## 1. Авторизация (`lib/pages/loginpage.dart`)

| Действие | Данные / ссылка |
|----------|-----------------|
| Вход | **E-mail**, **пароль** → `POST /api/autoriz1.php` (при наличии сохранённого FCM-токена он уходит в теле запроса). |
| Восстановление пароля | **E-mail** → `POST /api/request_password_reset.php`; затем **код из письма** и **новый пароль** (не менее 8 символов) → `POST /api/confirm_password_reset.php`. |
| Регистрация (кнопка с экрана входа) | Переход на `chagestatus` **только с `data: 1`** — то есть ветка **«регистрация заказчика»** (см. ниже). Другие роли из этого экрана не открываются. |
| Мессенджер | Кнопка **«Присоединиться к группе»** открывает в браузере: **https://t.me/+bocT1PzkmNIyZmQy** (`launchUrlString`). |
| Отдельной ссылки на сайт / политику на экране авторизации | Нет (кроме цепочки восстановления пароля через API). |

## 2. Регистрация: выбор роли и формы (`changestatis_page.dart`, `reguser*.dart`)

### 2.1. Шаг «Выбор статуса» — `chagestatus` (`lib/pages/changestatis_page.dart`)

Параметр **`data`** задаёт роль (**`rollNum`** дальше по цепочке):

| `data` | Подпись в AppBar | `RolNum` |
|--------|------------------|----------|
| 1 | заказчика | 1 |
| 2 | грузоперевозчика | 2 |
| 3 | усл. спецтехн | 3 |
| 4 | усл. грузчиков | 4 |

Далее пользователь выбирает радиокнопками (**`StatNum`**):

- **1** — «**Юр. лицо**»
- **2** — «**Физ. лицо**»

> **Замечание:** на экране ФИО (`reguser1_name.dart`) подзаголовок «Физ. лица» / «Юр. лица» привязан к **`RolNum`**, а не к `StatNum` — визуально может не совпадать с выбранным юр/физ. Логика ветвлений ниже опирается на **`statNum` и `rollNum` из кода**.

### 2.2. ФИО и город — `Creguser1_Name` (`lib/pages/reguser1_name.dart`)

- **Имя**, **отчество**, **фамилия**
- **Город (населённый пункт)** — выпадающий список из `GET /api/cities.php`

### 2.3. Телефон, e-mail, пароль, соглашение — `creguser3name` (`lib/pages/reguser3_page.dart`)

- **Телефон** — маска +7, валидация `+7` и 10 цифр
- **Эл. почта** — проверка формата
- **Пароль** — минимум **8** символов, **буквы и цифры**
- Галочка **«Принять пользовательское соглашение»** — по нажатию открывается ссылка:  
  **`http://gruzoperevozki72.ru/api/agreement.html`** (см. `_launchURL` в том же файле)
- Подтверждение e-mail: код через `POST /api/request_registration_code.php` и `POST /api/verify_registration_code.php`

**Куда идёт после шага 3** (упрощённо):

| Условие | Дальше |
|---------|--------|
| Заказчик физ (`rollNum==1`, `statNum==2`) или грузчик физ (`rollNum==4`, `statNum==2`) | Сразу `POST /api/regtest.php` → экран входа |
| Заказчик/перевозчик/спецтехника/грузчик **юр** (`statNum==1` для перечисленных в коде комбинаций) | Экран реквизитов **`creguser4_name_`** |
| Перевозчик физ (`rollNum==2`, `statNum==2`) | **`creguser_name`** — данные ТС (см. п. 3) |
| Спецтехника физ (`rollNum==3`, `statNum==2`) | **`creguser5_name_`** — вид спецтехники, затем цепочка к тарифам |

### 2.4. Юр. лицо: наименование, ИНН, КПП, ОГРН — `creguser4_name_` (`lib/pages/reguser4_page_.dart`)

- **Наименование**
- **ИНН** (контрольная сумма 10 или 12 знаков)
- **КПП** (ровно 9 цифр)
- **ОГРН / ОГРНИП** (13 или 15 цифр, проверка контрольного разряда)

Далее:

- **Заказчик или грузчик юр** (`rollNum` 1 или 4, `statNum==1`): отправка **`POST /api/regul.php`** с полями ФИО, город, телефон, email, пароль, namefirm, inn, ogrn, kpp → вход
- **Перевозчик юр** (`rollNum==2`, `statNum==1`): переход в **`creguser_name`** (ТС + тарифы)
- **Спецтехника юр** (`rollNum==3`, `statNum==1`): переход в **`creguser5_name_`** (вид спецтехники) → затем **`creguser2_name`**

### 2.5. Перевозчик (физ.): транспорт — `creguser_name` (`lib/pages/reguser_name.dart`)

- **Марка**, **год выпуска**
- **Грузоподъёмность** — список из `GET /api/get_vidgr.php`
- **Длина кузова**, **ширина кузова**
- **Вид кузова** — список из `GET /api/vidk.php`

Далее экран **`creguser2_name`** — тарифы:

- **Час** (ставка за час)
- **Смена**
- **Цена за км** (поле с подсказкой «150»)

Отправка регистрации исполнителя (перевозчик/спецтехника по веткам в коде): **`POST /api/register1.php`** (JSON с ФИО, контактами, реквизитами юрлица если были, полями ТС, `cenahaurs`, `cenasmena`, `cenakm` и т.д.) — см. `reguser2_page.dart`.

### 2.6. Спецтехника: вид техники — `creguser5_name_` (`lib/pages/reguser5_page_.dart`)

- **Вид спецтехники** — список из `GET /api/vidt.php`

Дальше для `rollNum==3` — переход на **`creguser2_name`** (тарифы без заполнения марки/грузоподъёмности в передаче — пустые строки в навигации), для других веток возможен переход в **`creguser_name`**.

## 3. Заказчик: поиск исполнителей (вкладка «Заказы»)

Экран: **`CustomerSearchScreen`** (`lib/pages/customer_search_screen.dart`), обёртка — `SearchFormisp.dart`.

| Поле | Источник |
|------|----------|
| **Поисковый запрос** | текст (опционально) |
| **Город** | `GET /api/cities.php` |
| **Услуга** | `GET /api/getsearsh.php` |

Классический путь без расширенного поиска: **Услуги** → город → `outputob` через `get_ads2_new.php`.

### 3.1. Быстрый подбор из «Мои объявления»

На карточке **активного** заказа (`ads2.dart`) — кнопка **«Найти исполнителей»** → `outputob` с параметрами из объявления (`lib/search/ad_match.dart`).

## 4. Заказчик: выбор типа заявки перед добавлением (`lib/pages/get_vt_z.dart` → `changerol_page2.dart`)

Сетка услуг → город → список объявлений. Кнопка «+» (после авторизации) → **`changerol1`**:

- Заказать **грузоперевозчика** → `add_ob_gp_usl`
- Заказать **спецтехнику** → `add_ob_gp_usl_t`
- Заказать **грузчика** → `add_ob_gp_usl_g`

### 4.1. Заказ грузоперевозки — `add_ob_gp_usl.dart` (заголовок «Добавить заказ»)

Поля (основные подписи в UI):

- **Грузоподъёмность** (справочник)
- **Откуда забрать** / **Куда доставить** — города
- **Дата погрузки** — варианты: «Как можно быстрее», «В период с… по…», «Не позднее чем» + выбор дат
- **Вид кузова** (`vidk`)
- **Тип перевозки** (полная / частичная / негабарит и т.п.)
- **Тип загрузки** (верхняя, боковая, гидроборт и т.д.)
- **Бюджет до** (число)
- **Подробнее о заказе** (текст)
- Фото груза / документы (до 4 снимков и др. по логике экрана)

### 4.2. Заказ спецтехники — `add_ob_gp_usl_t.dart` (также «Добавить заказ»)

Первое отличие в форме: блок **«Вид спецтехники»** (справочник `_vidt`), далее по смыслу схожие блоки с городами, датами, бюджетом, описанием и вложениями (см. файл целиком для полного списка).

### 4.3. Заказ грузчиков — `add_ob_gp_usl_g.dart` («Добавить заказ»)

Ключевые поля в начале формы:

- **Город**
- **Дата погрузки** (те же три варианта + даты)
- **Бюджет до**
- **Подробнее о заказе**
- **Прием заявок до** (дата)
- **Загрузить фото места работы** (до 4 изображений)

## 5. Исполнитель в приложении

Отдельной «регистрации исполнителя» с экрана **логина** в коде нет — только заказчик (`data: 1`). Регистрация **грузоперевозчика / спецтехники / грузчиков** предусмотрена в **`chagestatus`** при `data` 2–4; в текущем дереве навигации из `grep` вызовы **`chagestatus(data: 2|3|4)`** из других файлов **не найдены** — возможен заход с других экранов под другими именами или вне этого репозитория.

Профиль и объявления исполнителя редактируются в экранах вида `edit_ob_*.dart`, `add_ob_gp1.dart` и т.п. (отдельный краткий перечень полей можно добавить по запросу).
