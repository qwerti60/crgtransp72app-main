Этап 0 — Надёжность «под капотом»

ЭТАП 0

1. Поиск меньше нагружает сервер

Когда пользователь открывает форму поиска, приложение считает, сколько объявлений в каждом городе и по каждой услуге. Раньше это каждый раз шло тяжёлым запросом в базу.

Сейчас: цифры запоминаются примерно на 1 минуту. Повторное открытие формы проходит быстрее и легче для сервера.

2. Старые «дыры» в API закрыты

В проекте оставались старые адреса на сервере, которыми приложение уже не пользуется. Через них можно было получать данные по устаревшей логике.

Сейчас:
  • старые адреса поиска переводят на новый, правильный поиск;
  • один совсем устаревший адрес отключён;
  • дубликаты в папке api_new помечены как «не использовать».

3. Быстрая проверка после выкладки

Можно одной командой проверить, что поиск отвечает нормально — и для заказчика, и для исполнителя.

4. База готова к росту

Подготовлен файл с «указателями» (индексами) в базе, чтобы при большом числе объявлений поиск по городу не тормозил.

Важно: этот SQL нужно один раз выполнить на сервере БД:
sql/migrate_search_count_indexes.sql

Этап 1 — Доверие и спокойствие клиентов

ЭТАП 1

1. Жалобы и просмотр переписки в админке

Если по сделке возник спор, пользователь может нажать «Пожаловаться» прямо в чате с другой стороной.

Обращение уходит в поддержку. Оператор в админке видит жалобу и может открыть чат по сделке (только просмотр, без ответа в этот чат). Ответ пользователю — как обычно, через обращение поддержки.

2. Автоматические уведомления (push)

Пользователь получает уведомление, когда:

  • пришло новое предложение по заявке/объявлению;
  • заказ приняли к выполнению;
  • заказ отметили выполненным или отменили;
  • подписка исполнителя скоро закончится (за 3 дня) или уже закончилась.
Важно для подписки: на сервере нужно:
  1. выполнить SQL sql/migrate_subscription_push_dedupe.sql;
  2. поставить ежедневный запуск api/cron/subscription_push.php (как — в api/cron/README.md).

3. Короткий онбординг для новичков

После первой регистрации при первом входе показываются 3 коротких экрана:

  • что сделать с профилем;
  • как разместить объявление/заявку;
  • как устроена сделка (или подписка — для исполнителя).

Можно нажать «Пропустить» и сразу перейти в приложение.

Дополнительные пакеты P1–P3 (смета 07.2026)

P1

Старт — быстрый эффект

сделано 02.08.2026
  • Геопоиск «рядом со мной» — радиус и сортировка по расстоянию в поиске; координаты городов в админке.
  • Жалобы — кнопка в приложении; очередь в админке «Поддержка»; просмотр переписки по сделке.
  • Push-уведомления — отклики, этапы сделки; напоминания об окончании подписки (cron).
  • Пакеты подписки — месяц / квартал / год и промокоды; настройка в админке «Пакеты» и «Промокоды».

Архив для сервера: dist/p1_deploy_*.zip

P2

Рост — удержание и монетизация

сделано 03.08.2026
  • Онбординг — три экрана-подсказки после первого входа в приложение.
  • Платное поднятие объявления — «в топ» на 24 или 72 часа; тарифы в админке «Поднятие».
  • Галочка «Проверен» — у исполнителя после проверки документов; видна заказчикам в поиске.
  • Шаблоны заявок — заказчик создаёт новую заявку «как прошлую» одной кнопкой.
  • Статус «В пути» + время прибытия — исполнитель отмечает в сделке; заказчик получает push.
  • Воронка в статистике — наглядная цепочка: регистрации → объявления → отклики → сделки → оплаты.

Архив: dist/p2_deploy_*.zip · нужна сборка Flutter (новые экраны в приложении).

P3

Масштаб — B2B и операционка

сделано 03.08.2026
  • Счета для юрлиц (B2B) — исполнитель-организация запрашивает счёт в приложении; менеджер выставляет и отмечает оплату в админке «Счета B2B».
  • Автомодерация объявлений — стоп-слова, отклонение без фото, дубли в очередь; раздел «Автомодерация».
  • Экспорт CSV — выгрузка пользователей, оплат подписки и сделок для бухгалтерии.

Архив: dist/p3_deploy_20260803.zip
